# Технический план реализации (Plan)

Этот документ содержит технические подробности реализации новых возможностей бота, структуру данных и интеграцию с API.

## 💾 Расширение структуры кэша и типов данных

1. В `src/types.ts` добавим типы для констант предметов и популярности предметов:
   ```typescript
   export type DotaItem = {
     id: number;
     name: string; // системное имя (например, "item_tango")
     localized_name: string; // читаемое имя ("Tango")
     cost: number;
     recipe: number; // 1 если рецепт, 0 иначе
     secret_shop: number;
   };

   export type HeroItemPopularity = {
     start_game_items: Record<string, number>;
     early_game_items: Record<string, number>;
     mid_game_items: Record<string, number>;
     late_game_items: Record<string, number>;
   };

   // Расширенный DotaCache
   export type DotaCache = {
     source: "opendota";
     updatedAt: string;
     heroes: OpenDotaHero[];
     matchups: Record<string, HeroMatchup[]>;
     items: Record<string, DotaItem>; // кэш констант предметов
     itemPopularity: Record<string, HeroItemPopularity>; // кэш популярности предметов по героям (heroId -> popularity)
   };
   ```

2. В `src/data/opendota.ts` добавим функции:
   * `fetchItemsConstants()` -> получает константы предметов с `https://api.opendota.com/api/constants/items`.
   * `fetchHeroItemPopularity(heroId: number)` -> получает популярность предметов для конкретного героя с `https://api.opendota.com/api/heroes/${heroId}/itemPopularity`.

---

## 🔄 Обновление логики фонового сборщика

1. В `src/data/refresh.ts` при первом обновлении данных:
   * Скачиваем список всех героев.
   * Скачиваем константы предметов с OpenDota и сохраняем их в кэш.
2. При запросе команд, связанных с предметами конкретного героя (`/hero` или логика `/items`):
   * Если данных о предметах героя нет в кэше, лениво скачиваем их через `fetchHeroItemPopularity` и сохраняем в `cache.json`.

## 🧠 Реализация бизнес-логики (Services)

### 1. Предметы по позициям (`/items`)
* Так как в API нет популярности предметов «вообще для позиции Carry», мы рассчитываем это динамически:
  1. Находим топ-3 лучших героев для выбранной позиции (через `getMeta(position)`).
  2. Для каждого из этих героев берем их популярные предметы из кэша (загружая по сети, если их там нет).
  3. Суммируем популярность предметов по стадиям игры (`early_game_items`, `mid_game_items`, `late_game_items`).
  4. Исключаем рецепты, расходники (Tango, Flask, Ward, Clarities в поздних стадиях) и дешевые промежуточные предметы для поздней стадии.
  5. Берем топ-4 самых популярных предметов для каждой стадии и выводим их с названиями и ценами.

### 2. Неэффективные предметы по позициям (`/bad_items`)
* Применяем эвристику на основе несоответствия ролей:
  * Для **саппортов** (support4, support5) неэффективными считаются дорогие предметы на чистый физический урон/фарм (например: Battlefury, Daedalus, Radiance, Butterfly, Manta Style).
  * Для **керри** (carry) неэффективными считаются чистые саппорт-предметы (например: Glimmer Cape, Force Staff, Mekansm, Pipe of Insight), если они не подходят под специфические гибридные сборки.
  * Для **мидеров/оффлейнеров** выводим предметы, которые имеют крайне низкую синергию с их основными задачами (например, Hand of Midas в мете быстрого темпа или предметы, не соответствующие их типу атаки).
* Выводим список из 4-5 таких предметов с забавным предупреждением от бота.

### 3. Связки на линии (`/lane_combo`) и Синергия (`/game_combo`)
* В `src/services/metaService.ts` разделим `/synergy` на две более точные команды:
  * `/lane_combo`: подбирает героев противоположной роли для линии (если выбран керри ближнего боя — ищет дальнего саппорта с лечением/харасом, если выбран оффлейнер-инициатор — ищет активную четверку с контролем).
  * `/game_combo`: подбирает комбинации по игре на основе синергии способностей (например, АОЕ контроль под АОЕ ультимейт — Chronosphere + Cataclysm, или сейв под агрессивного керри).

### 4. Карточка героя (`/hero`)
* Собирает всю информацию о герое в красивое Embed-сообщение:
  * Основные роли и базовый винрейт/пикрейт.
  * Лучшая позиция (на основе весов из `positions.ts`).
  * Популярные стартовые и основные предметы.
  * Топ-3 лучших матчапа (кого контрит) и топ-3 худших матчапа (кто его контрит).
