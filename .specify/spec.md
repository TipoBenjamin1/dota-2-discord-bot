# Спецификация требований (Specification)

Этот документ описывает пользовательские сценарии и функциональные требования к Discord-боту Dota 2.

## 🎯 Цели и сценарии использования

Бот предназначен для помощи игрокам во время стадии пиков и планирования матча. Игрок может быстро узнать текущую мету, контрпики против вражеских героев, синергичные связки, а также рекомендуемые предметы для разных позиций.

### Сценарии:
1. **Сценарий 1 (Анализ меты):** Пользователь пишет `/meta` или `/meta position:Carry` и видит топ-5 лучших героев для выбранной роли с указанием их винрейта, пикрейта и причин, почему они сильны.
2. **Сценарий 2 (Контрпик врага):** Враг выбрал героя `Anti-Mage`. Пользователь пишет `/counter hero:Anti-Mage` и видит по 3 лучших контрпика для каждой из 5 позиций.
3. **Сценарий 3 (Выбор предметов):** Пользователь играет на позиции Mid за случайного героя или хочет узнать общие тренды. Он пишет `/items position:Mid` или запрашивает информацию по конкретному герою, чтобы увидеть лучшие стартовые, ранние, средние и поздние предметы.
4. **Сценарий 4 (Подбор связки):** Игрок взял Juggernaut на линию Carry. Саппорт пишет `/lane_combo hero:Juggernaut` и получает список лучших саппортов для синергии на линии с объяснением причин.

## 💻 Спецификация слэш-команд

Бот должен поддерживать следующие команды:

1. `/meta [position]`
   * **Параметры:** `position` (опционально, выбор из 5 позиций).
   * **Результат:** Топ-5 лучших героев на указанных позициях с их винрейтом и пикрейтом.

2. `/worst [position]`
   * **Параметры:** `position` (опционально).
   * **Результат:** Топ-5 самых слабых героев (с учетом винрейта и выборки матчей).

3. `/counter hero [position]`
   * **Параметры:** `hero` (строка, имя героя, автодополнение или поиск), `position` (опционально).
   * **Результат:** По 3 лучших контрпика с указанием винрейта матчапа.

4. `/synergy hero`
   * **Параметры:** `hero` (строка).
   * **Результат:** Герои, имеющие общую синергию (по игре в целом).

5. `/lane_combo hero`
   * **Параметры:** `hero` (строка, имя героя на линии).
   * **Результат:** Лучшие партнеры на линию (Carry + Hard Support или Offlane + Soft Support).

6. `/game_combo hero`
   * **Параметры:** `hero` (строка).
   * **Результат:** Лучшие связки по игре после стадии лайнинга (комбинации ультимейтов, инициация).

7. `/items position`
   * **Параметры:** `position` (выбор из 5 позиций).
   * **Результат:** Лучшие предметы по стадиям игры для выбранной позиции (на основе агрегированной популярности героев этой роли).

8. `/bad_items position`
   * **Параметры:** `position` (выбор из 5 позиций).
   * **Результат:** Предметы, которые имеют худший винрейт или не рекомендуются для героев этой позиции.

9. `/hero hero`
   * **Параметры:** `hero` (строка).
   * **Результат:** Карточка героя со сводной статистикой (роли, винрейт, пикрейт, баны, лучшие позиции и популярные предметы).

10. `/patch`
    * **Результат:** Сводка об актуальности данных (время последнего обновления кэша и количество героев в базе).

## 🔄 Обновление данных

* Базовый кэш героев (`heroes`) загружается регулярно из API OpenDota `/heroStats`.
* Детализированные матчапы (`matchups`) и популярность предметов (`itemPopularity`) запрашиваются лениво по мере обращения пользователей к соответствующим героям и сохраняются в кэш.
* В кэше хранится справочник предметов (`items`) для быстрого сопоставления ID предметов с их названиями и иконками.
