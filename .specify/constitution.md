# Конституция проекта (Constitution)

Этот документ определяет руководящие принципы разработки, стандарты кодирования и правила взаимодействия компонентов в проекте Dota 2 Discord Bot.

## 🛠️ Стек технологий и стандарты кода

1. **Среда выполнения и язык:**
   * Node.js (версия >= 20).
   * TypeScript в строгом режиме (`strict: true` в `tsconfig.json`).
   * Использование Node ESM (ECMAScript Modules). Все локальные импорты должны содержать расширение `.js` (например, `import { x } from "./y.js"`).

2. **Работа с Discord:**
   * Библиотека `discord.js` v14.
   * Все слэш-команды регистрируются глобально или локально для гильдии с помощью REST API Discord.
   * Ответы на команды должны быть быстрыми. Обязательно использование `interaction.deferReply()` для команд, которые могут выполняться дольше 3 секунд (например, при обращении к кэшу или внешнему API).

3. **Стиль и эстетика интерфейса:**
   * Все ответы пользователям оформляются на русском языке.
   * Вместо простого текста используются **Discord Embeds** (встроенные сообщения) с цветовым кодированием:
     * Зеленый/Синий для высокого винрейта или полезных рекомендаций.
     * Оранжевый/Красный для низкого винрейта или слабых героев.
     * Красочные эмодзи ролей и типов атак.

---

## 💾 Управление данными и кэширование

1. **Единственный источник правды:**
   * Все данные берутся из OpenDota API.
   * Справочник предметов получается из эндпоинта констант (`/constants/items`).
   * Статистика популярности предметов для героев берется из эндпоинта `/heroes/{hero_id}/itemPopularity`.

2. **Стратегия кэширования:**
   * Бот не должен делать запросы к OpenDota API при каждом действии пользователя, чтобы не превысить лимиты (rate limit).
   * Данные о героях и предметах кэшируются локально в `data/cache.json`.
   * Кэш обновляется в фоновом режиме раз в час (или по заданному интервалу).
   * При получении данных о контрпиках или предметах конкретного героя, они лениво догружаются и дозаписываются в кэш.

3. **Обработка ошибок:**
   * В случае сбоя API бот должен использовать последние успешно закэшированные данные.
   * Все ошибки API или обработки логируются в консоль, а пользователю отправляется понятное сообщение об ошибке.
